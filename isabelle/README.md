# isabelle

The combinatorial core of [`docs/FASS_THEOREM.md`](../docs/FASS_THEOREM.md) as an
Isabelle/HOL session, in the same spirit as the Lean check in [`lean/`](../lean/)
for selection 15: the kernel re-runs every finite computation, and the
all-levels statements are proved from them by induction.

## Files

| file | content |
|---|---|
| `FASS_Core.thy` | table types; direction-map algebra; the substitution step on words; the word claims, their expansion, and the theorem `claims_all_levels` (closure + base at level 1 ⟹ every level); the same for leaf labels; the executable checks C1, C3, C4, C5, C6, C7; the routing operator `Fstep` and `routing_all_levels` (a period-2 orbit with zero circuits and a one-arc Psi ⟹ every level) |
| `FASS_Data_Hex.thy`, `FASS_Data_Spectre.thy` | generated by `web/fass-theorem/06-isabelle-data.ts`: the tables of `01-tables.ts`, the level-1 words and labels, the level-1 corners, the dot indicators of the configuration, and the level-1 routing states read from exact geometry |
| `FASS_Hex.thy`, `FASS_Spectre.thy` | the `by eval` checks on the data and the resulting theorems for configurations (A) and (B) |
| `shadow.py` | a Python transliteration of every executable definition of `FASS_Core.thy`, run on the data theories; it confirms that each `by eval` statement is a true closed computation |
| `ROOT` | the session |

## Checking

```
isabelle build -D isabelle
python3 isabelle/shadow.py      # no Isabelle needed
```

**Status.** The session was written in an environment with no Isabelle
installation and no network route to the Isabelle distribution, so it has not
been run through Isabelle yet. Two things mitigate that. Every `by eval` line
was validated by `shadow.py`, an independent implementation of the same
definitions, so the computational claims are true; and the general proofs
(`holds_step`, `claims_all_levels`, `funpow_period_all`, `routing_all_levels`,
`angles_all_levels`) are short Isar proofs over `Main` only, written to be
robust rather than clever. Expect at most small syntax or automation repairs
when the session is first built. If a proof step fails, the mathematics it
encodes is in `docs/FASS_THEOREM.md` §3 (C2) and §5.

## What is and is not formalised

Formalised: everything in the write-up that is a finite computation on the
tables, and the inductions that carry those computations to every level. The
theorems `hex_words_all_levels`, `hex_labels_all_levels`,
`hex_angles_all_levels`, `hex_routing_all_levels`, `hex_dot_counts_all_levels`
(and the `spec_` twins) are genuine statements about all `k`.

Not formalised, because it is geometry rather than combinatorics: that the
tables describe the actual level-1 and level-2 patches (`01-tables.ts`, exact
arithmetic), the validity of those patches (winding number, Lemma 1.1), the
covering-space argument of §4, and the vertex stars and chord crossings of §6.
These are the inputs of the development, exactly as V0b and V6 are the inputs
of the Lean development in `lean/`.
