### UI/UX Plan for Spectre Tile Combination Explorer

This plan outlines a user interface for exploring valid edge combinations of Spectre tiles, focusing on interactivity, clarity, and powerful analysis tools.

#### 1. Overall Vision & Layout

The UI will be a single-page application with three main sections:

*   **Control Panel (Left Sidebar):** A collapsible sidebar containing all the controls for selecting edge subsets, exploring combinations, and filtering the results.
*   **Visualization Canvas (Center):** A large area to display the generated tile patterns in real-time.
*   **Analysis Panel (Right Sidebar):** A panel to display the results of the graph and circuit analysis of the current tiling.

This layout provides a clear separation of concerns and allows the user to see the effects of their choices immediately.

#### 2. Control Panel Components

This panel will be the primary interaction point for the user.

*   **Edge Subset Selector:**
    *   **UI:** A dropdown menu or a set of radio buttons at the top of the panel.
    *   **Labels:** Each option will be one of the 8 "kernel" subsets of valid edges you mentioned. We will need to identify these from the Colab notebook.
    *   **Behavior:** Selecting a subset will trigger the generation of all possible edge pairings for each tile type within that subset. This will update the "Combination Explorer".

*   **Combination Explorer:**
    *   **UI:** This will be a dynamic list of controls, one for each of the 10 tile types (`Delta`, `Theta`, `Lambda`, `Xi`, `Pi`, `Sigma`, `Phi`, `Psi`, `Gamma1`, `Gamma2`).
    *   **Reordering:** Each tile control will be a draggable element, allowing you to reorder the list. This directly corresponds to your idea of reordering the "digits" in the mixed-radix number.
    *   **Combination Scrubber:** Each tile control will feature a slider. The slider's value will represent the selected combination for that tile. The max value of the slider will be the total number of valid combinations for that tile.
    *   **Behavior:**
        *   Moving a slider will update the tiling visualization in real-time.
        *   The sliders will be linked in a "mixed-radix" fashion. For example, if you drag the slider for the first tile in the list to its maximum value and then move it one more step, it will reset to zero and increment the slider of the next tile in the list by one. This creates the "odometer" or "number in a base" effect you described.
        *   Dragging and dropping a tile control to a new position in the list will change its significance in the "mixed-radix" system, allowing you to explore the combination space in different ways.

*   **Filtering and Options:**
    *   **UI:** A set of checkboxes.
    *   **Options:**
        *   `[x] Non-crossing lines`: When checked, this will filter out any combinations that result in crossing edges. This will dynamically update the max value of the sliders in the Combination Explorer.
        *   `[ ] Show Edge Labels`: Toggles the visibility of the edge labels on the tiles in the main visualization.
        *   `[ ] Show Analysis`: Toggles the visibility of the Analysis Panel.

#### 3. Visualization Canvas

*   **UI:** A large, zoomable, and pannable canvas that takes up the majority of the screen.
*   **Behavior:**
    *   The canvas will render the Spectre tiling based on the current selections in the Control Panel.
    *   Updates will be in real-time as the user interacts with the controls.
    *   When a user hovers over a tile control in the Combination Explorer, the corresponding tiles in the visualization could be highlighted to provide a clear connection between the controls and the output.

#### 4. Analysis Panel

*   **UI:** A sidebar that can be toggled on and off.
*   **Content:** This panel will display the results of the graph analysis of the current tiling. This will include:
    *   **Component Analysis:**
        *   Number of disconnected components.
        *   A list of components, with the number of tiles in each.
    *   **Circuit/Leaf Analysis:**
        *   Number of circuits (closed loops of connected tiles).
        *   Number of leaves (linear chains of tiles).
        *   Number of other, more complex structures.
    *   **Visual Representation:** We could include a simplified, non-geometric graph diagram of the connections between tiles to make the structure more apparent.

### Underlying Logic and Implementation Notes

*   **Data Pre-computation:** When an edge subset is selected, we will pre-compute all possible valid edge combinations for each tile type, both with and without the "non-crossing" constraint. This will make the UI fast and responsive. The functions `generate_map_of_valid_combinations` and `filter_non_crossing_combinations` from `graph-utils.js` will be used here.
*   **State Management:** A central state object will hold the current selections for the edge subset, the combination for each tile, the order of the tiles, and the filter settings. All UI components will read from and update this state object.
*   **Graph Analysis:** The `get_adj`, `find_components`, and `leaves_circuits_other` functions will be used to perform the analysis on the current tiling. This analysis can be run in a web worker to avoid blocking the UI thread if it becomes computationally intensive for large tilings.

By following this plan, we can create a powerful and intuitive tool for exploring the rich combinatorial space of Spectre tilings. The UI is designed to be interactive and to provide immediate feedback, which is key for this kind of exploratory work.
